## 这个应用现在是干什么的

作业 PDF 没有规定主题，也没有写「入场票」或「活动报名」。它要求小组自己有一个 story/idea，报告里要有 background 这一章，内容由小组来写。

老师教程和示例仓库里的功能是：连接钱包，调用 `mint()`，领取一张 NFT，每个地址一次。合约名字是 `Ticket NFT`，按钮文字是领票。这是教学示例里的操作，不是 PDF 写好的作业背景。

小组场景写在仓库 `README.md` 的「故事」一节：免费讲座有 50 个座位，同学领票、转让给另一同学或退回主办方，主办方再按票号核销。主办方就是部署者钱包。详细规则以 `docs/03-转让退票与票务流程.md` 为准。这不是老师 PDF 的原文，功能还没写。

部署合约是成员 2 在 Remix 里做的一次开发步骤，网页上没有「部署」或「发币」按钮。Lab 3 的 ClubToken 才是发一种 ERC-20 币，那是另一份作业。

## 故事线

全文在 `README.md`，规则在 `docs/03-转让退票与票务流程.md`。四个操作都还没实现：

1. 同学领取，座位减一；同一地址最多持有一张有效票。
2. 未核销票可以转给另一合资格同学，入场资格跟随当前所有者，剩余座位不变。
3. 未核销票可以退回部署者，座位加一；下一次领取优先复用退回的票号。
4. 部署者按票号核销当前持有人；已核销票留作纪念，不能再转让、退票或重复入场。

## 每个人的完成标准

### 1. 组长 / 集成

- README 里的命令，换一台电脑能把页面打开。
- `.env` 没有被提交。合约地址只出现在 `.env`，例子放在 `.env.example`。
- 合约部署后，把 Sepolia 合约地址和一笔成功交易的链接记进 README。
- 协调新接口，准备部署者和演示同学钱包；彩排转让、退票、同票号重新领取和核销。
- 合并别人的分支前，自己先 `npm run dev` 点一遍。

### 2. 合约

- `contracts/` 里有小组自己的 Solidity，并说明它和老师示例差在哪。
- 完成 `docs/03` 的四个操作，核销限部署者；所有转移入口统一维护资格、票状态和座位计数，退票池复用同一票号。
- 用 Remix 部署到 Sepolia，把合约地址交给组长。不要部署到 Remix VM。
- 在报告 Implementation 里写：编译器版本、网络、合约地址、核心函数、一次失败会怎样（例如重复领取）。

### 3. 钱包与交易

改 `src/wallet/ethereum.js`。保留 `connectAccount`、`claimTicket`；新增 `transferTicket(to, tokenId)`、`returnTicket(tokenId)`；现有 `admitStudent` 改为接收 `tokenId`，调用合约的 `admit(uint256)`。连接和切到 Sepolia 的写法见 `docs/01`。四个写操作都要等打包并返回交易哈希，失败时提供错误信息。

### 4. 前端界面

- 没连钱包、交易进行中、成功、用户拒绝、合约报错，这几种状态都要有一句人能看懂的话。
- 成功后给出 Etherscan 链接，哈希和钱包里的是同一笔。
- 样式放在 CSS 或 `src/ui/`，不要把钱包逻辑写进页面文件。
- 新建 `TicketPage.jsx`，将转让、退票和票状态集中放在我的门票页；领票成功后跳转 `#ticket`。入场页按票号查询当前持有人；已核销票显示纪念状态，不能继续转让或退票。
- 全局钱包弹窗支持未安装钱包、用户拒绝、网络错误、连接成功后返回；交易确认、等待和失败按 `docs/04` 展示。主办方页面按合约 `organizer()` 判断权限。

### 5. 报告、视频、只读状态

- 按 `docs/report/大纲.md` 收齐五章，最后导出 PDF。
- 英文视频不超过 15 分钟，里面有现场演示。分镜写在报告目录里。
- 在 `src/chain/read.js` 保留 `readRemaining`；用 `readActiveTicket(account)`、`readHasEntered(account)` 替代旧的 `readHasClaimed`、`readAdmitted`，新增 `readTicket(tokenId)`（当前所有者与状态）和 `readOrganizer()`。只读不弹确认窗。
- 报告说明 NFT 转让后资格跟随所有者、退票释放名额并复用票号、核销后冻结。视频成功链路见 `docs/03`。
