## 这个应用现在是干什么的

作业 PDF 没有规定主题，也没有写「入场票」或「活动报名」。它要求小组自己有一个 story/idea，报告里要有 background 这一章，内容由小组来写。

老师教程和示例仓库里的功能是：连接钱包，调用 `mint()`，领取一张 NFT，每个地址一次。合约名字是 `Ticket NFT`，按钮文字是领票。这是教学示例里的操作，不是 PDF 写好的作业背景。

小组场景写在仓库 `README.md` 的「故事」一节：免费讲座有 50 个座位，同学领票、转让给另一同学或退回主办方，主办方再按票号核销。主办方就是部署者钱包。详细规则以 `docs/03-转让退票与票务流程.md` 为准。这不是老师 PDF 的原文。合约与完整 ABI 已实现，已部署 Sepolia 并通过初始核验；正式钱包、只读查询和页面仍待实现。

部署合约是成员 2 的开发步骤，本次通过本地部署辅助页与 MetaMask 完成，Remix 步骤保留作备用。正式业务网页不安排「部署」或「发币」按钮。Lab 3 的 ClubToken 才是发一种 ERC-20 币，那是另一份作业。

## 故事线

全文在 `README.md`，规则在 `docs/03-转让退票与票务流程.md`。以下四个操作已写入并部署合约，已完成领取 → 退票 → 重领验收，转让 / 核销仍需正式网页联调演示：

1. 同学领取，座位减一；同一地址最多持有一张有效票。
2. 未核销票可以转给另一合资格同学，入场资格跟随当前所有者，剩余座位不变。
3. 未核销票可以退回部署者，座位加一；下一次领取优先复用退回的票号。
4. 部署者按票号核销当前持有人；已核销票留作纪念，不能再转让、退票或重复入场。
